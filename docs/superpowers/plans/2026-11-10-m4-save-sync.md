# M4 — Memory-card save sync — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Memory cards of online-library games follow the owner between devices; conflicts keep both cards (cloud wins, the other is downloaded).

**Spec:** [save-sync design](../specs/2026-11-10-save-sync-design.md) (approved 2026-11-10: memcard only, cloud-wins-and-download conflict rule). Deviation recorded here: the card fingerprint is **FNV-1a 64 (hex)**, computed synchronously, because the `saveDatabaseLoaded` hook cannot await WebCrypto; AES-GCM provides integrity.

## Global Constraints
- `saveKey` = Crockford base32 of the first 14 bytes of HKDF(K_game, `"save:memcard"`) → 23 chars (same shape as object keys). Card key = HKDF(K_game, `"save-key"`) as AES-GCM. Ciphertext = `iv(12, random) || AES-GCM(plain, AAD = utf8(saveKey))`. Plain = `u64 BE updatedAt || 16-char ASCII hex fingerprint || card bytes`.
- Server routes owner-only: `GET|PUT|DELETE /api/lib/:id/saves/:saveKey`; PUT body 1 B – 1 MiB; stored at `lib/{id}/save/{saveKey}`; size counted in `objects` (key `save:{saveKey}`) toward quota; never readable with a share.
- Local meta in settings `saveSync.<saveKey>` = `{ updatedAt: number, hash: string }` = the version this browser last uploaded or pulled.
- Card path in the emulator FS: `/data/saves/PCSX-ReARMed/<EJS_gameName without extension>.srm`.
- Only `source = cloud` syncs. Strings in en.json; TDD; commit per task.

## Review Focus
1. Offline start → game starts with the local card, indicator "Not synced", no data loss; the next successful save uploads.
2. Conflict → cloud card injected, local card downloaded as a file, notice shown.
3. Tampered save object → ignored with a notice (game starts with the local card), never crashes the boot.
4. Two quick saves → never two PUTs in flight; the last card wins.
5. Deleting the game deletes its save object.

### Task 1: Save crypto + decision (shared, pure)
- `shared/utils/saveSync.ts`: `fingerprint(bytes): string`; `deriveSaveKeys(kGame) → { saveKey, key }`; `sealSave(key, saveKey, card, updatedAt) → Uint8Array`; `openSave(key, saveKey, bytes) → { card, updatedAt, hash }` (throws on tamper); `decideOnStart({ local, meta, cloud }) → { action: 'none' | 'pull' | 'push' | 'conflict'; inject?: Uint8Array; keepLocal?: Uint8Array }`.
- Rules: no cloud → push if local else none. cloud equals local → none (meta refresh). local null or unchanged since meta → pull. local changed and cloud.hash === meta.hash → push. otherwise conflict.
- Tests: round-trip, tamper/wrong-key/AAD rejects, IV differs per seal, every decision branch.

### Task 2: Server routes
- Service: `getSave`, `putSave` (quota via store objects with key `save:<k>`), `deleteSave`. Routes under `server/api/lib/[id]/saves/[saveKey].{get,put,delete}.ts` with `ownerAction`. Tests in libraryService tests: put/get/overwrite counts size once, delete frees, share header refused (route-level via readerAction not used).

### Task 3: Client sync engine
- `cloudApi`: `getSave(saveKey) → Uint8Array | null`, `putSave(saveKey, bytes)`, `deleteSave(saveKey)`.
- `app/utils/saveSyncClient.ts`: `createSaveSync({ api, kGame, title, getMeta, setMeta, now })` → `{ prepare(): Promise<void> /* fetch cloud + meta */, onFsReady(fs, path): StartResult /* sync */, onCardSaved(bytes): void /* debounced single-flight push */, status: Ref<'idle'|'synced'|'offline'|'error'>, lastSyncedAt: Ref<number|null> }`.
- Tests with fake api: all decision paths, single-flight (second save while first PUT pending → exactly 2 PUTs total, last bytes), offline PUT → status offline then success → synced, tampered cloud → notice + local kept.

### Task 4: Emulator + player integration
- `useEmulator.start` options `onFsReady?(fs)`, `onCardSaved?(bytes)` (subscribe `saveSaveFiles` in `EJS_ready`).
- Player `source=cloud`: `prepare()` before `start`, hook up, indicator in `PlayerOverlay` (`save.synced`, `save.offline`), conflict → download local card + notice.
- `useCloudLibrary.deleteGame` deletes the save object.
- Tests: PlayPage cloud passes hooks and shows indicator; deleteGame calls deleteSave.

### Task 5: E2E + deploy
- E2E: PC 1 plays a cloud game, writes a known card via the emulator's import path and flushes → PC 2 plays the same game → the card in its FS equals PC 1's. Manual checklist `docs/manual-tests/m4.md`. Deploy, prod smoke for saves routes.
